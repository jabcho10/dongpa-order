# 동파 주문 지시서

SOXL 7티어 순환 매매(동파 전략)의 당일 LOC·MOC 주문을 산출하는 페이지.
시세는 GitHub Actions가 매 거래일 갱신하므로 PC 전원과 무관하게 최신 상태가 유지된다.

**페이지:** `https://<사용자명>.github.io/<리포지토리명>/`

## 구성

| 파일 | 용도 |
|---|---|
| `index.html` | 주문 지시서 (GitHub Pages가 서빙) |
| `market.json` | 시세 + 최근 60거래일 이력 — 워크플로가 매 거래일 갱신 |
| `update_market.py` | 시세 산출 및 `market.json` 갱신 |
| `.github/workflows/update-market.yml` | 화~토 07:07 KST 예약 실행 |

페이지는 같은 폴더의 `market.json`을 읽는다. 읽지 못하면 HTML에 내장된 대체값으로 동작하므로
어떤 경우에도 주문 산출은 가능하다.

## 자동 갱신

평일 22:07 UTC(= 화~토 07:07 KST)에 실행된다. 미 증시 마감(16:00 ET = 05:00~06:00 KST)
이후이므로 당일 종가가 확정된 뒤다. 23:37 UTC에 재시도용으로 한 번 더 돈다.

```
SOXL 최근 종가  ─┐
QQQ 주간 RSI(14) ┴─> market.json ─> 커밋 ─> Pages 반영
```

종료코드로 상태를 구분한다. **0** 갱신함(커밋) / **10** 변경 없음(아무것도 안 함) / **1** 실패.

### 안전장치

- **미확정 종가 차단** — Yahoo는 방금 마감된 세션의 봉을 `Open`·`Volume`만 채운 채
  `Close=NaN`으로 잠시 내려준다. 이때 NaN을 건너뛰고 그 전날 종가를 쓰면
  **이미 지나간 세션용 주문**이 만들어진다. 15초 간격 2회 재시도 후에도 확정되지 않으면
  `market.json`을 그대로 두고 실패 처리한다.
- **신선도 가드** — 최근 확정 종가가 4일을 넘으면(주말·공휴일 감안) 데이터 이상으로 보고 중단한다.
- **페이지 경고** — 기준 종가일이 4일을 넘기면 상단에 적색 배너가 뜬다.
- 갱신 실패 시 이전 종가가 그대로 남으므로, 잘못된 값으로 주문이 산출되지는 않는다.

## 주간 RSI 산출 방식

1. `Adj Close` 일봉 (종가 아님 — 배당조정가)
2. 주별 **실제 마지막 거래일** 종가로 주봉 구성 (금요일이 휴장이면 그 전 거래일)
3. **Wilder 평활** RSI(14) — 단순이동평균 방식 아님
4. 각 거래일에 **전주** 마지막 거래일의 RSI를 적용 (`RSI ≥ 50` → 공세모드)

## 자동 반영

**기준점**(기준 거래일 + 그날 마감 시점의 보유 현황·현금·시드)에서 출발해, `market.json` 의
`history`(최근 60거래일의 확정 종가와 그날 적용 RSI)로 하루씩 확정 규칙을 돌려 현재 상태를
계산한다. 순서는 규칙서 §8과 같다: 장 시작 빈 티어 → 주문수량 → 매도·청산 → 매수 체결 →
사이클 종료 판정 → 보유일 +1. 며칠 페이지를 열지 않아도 이력 범위 안이면 따라잡는다.

상태를 누적해서 고치지 않고 **매번 기준점에서 처음부터 다시 계산한다.** 그래서 같은 구간이
두 번 반영되는 일이 없고, 기준일만 바꾸면 언제든 그 시점부터 다시 계산된다.

| 하고 싶은 것 | 방법 |
|---|---|
| 실제 체결이 계산과 다를 때 고치기 | 티어 표·현금·시드를 직접 수정 — 그 상태가 곧 새 기준점이 된다 |
| 지금 상태를 확정하기 | **현재 상태를 기준으로 고정** 버튼 |
| 특정 날짜부터 다시 계산하기 | **기준 거래일** 을 그 날짜로 변경 |
| 방금 한 변경 취소 | **되돌리기** 버튼 |
| 전부 손으로 관리하기 | **자동 반영** 체크 해제 (다시 켜면 그 시점 상태를 기준으로 잡는다) |

- 처음 열 때는 **기준일만 잡고 아무것도 반영하지 않는다.** 보유 현황이 그 날짜 마감 기준인지
  확인한 뒤 사용한다.
- 기준일을 과거로 되돌리면 그날 마감 상태의 스냅샷으로 되돌린 뒤 다시 재생한다. 스냅샷이 없는
  날짜(기준점보다 이전)면 지금 표에 있는 상태를 그날 것으로 보고 계산하며, 그 사실을 알린다.
- 사이클 도중에 기준일을 잡으면 그 사이클의 누적 손익을 알 수 없다. 이때는 사이클이 끝나도
  가상 시드를 자동 갱신하지 않고 로그로 알린다.
- 이 엔진은 `dongpa_backtest.py` 와 같은 결과를 낸다(2026-06-23~09-15 83건 일치 검증).

## 저장 범위

| 항목 | 출처 | 저장 |
|---|---|---|
| 전일 종가, 주간 RSI, 주문일, 기준 종가일 | `market.json` | 저장하지 않음 (매 거래일 갱신) |
| 사이클 시드, 실제 현금, 7티어 보유 내역 | 브라우저 `localStorage` | 저장 (이 브라우저에만) |
| 자동 반영 기준일·내역 | 브라우저 `localStorage` | 저장 (이 브라우저에만) |

시세를 화면에서 수동으로 고쳐도 저장되지 않고 다음 갱신 때 되돌아간다.
보유 내역은 브라우저에만 남으므로 공개 페이지라도 외부에 노출되지 않는다.
다른 기기·브라우저에서는 보유 내역을 다시 입력해야 한다.

## 최초 설정

1. 이 디렉터리를 **공개** 리포지토리로 push
2. Settings → Pages → Source: **Deploy from a branch**, Branch: `main` / `/ (root)`
   — 사이트 파일은 리포지토리 루트에 있다. `/docs` 로 두면 루트 URL이 README를 보여준다.
3. Actions 탭 → `시세 자동 갱신` → Run workflow 로 동작 확인

전략 확정 규칙과 백테스트 엔진은 별도 비공개 리포지토리에 있다.
